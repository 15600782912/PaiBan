# 主播排班与个人工时 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Implement inline, then request one whole-project review.

**Goal:** Deliver the approved native WeChat mini program and FastAPI/SQLite application.
**Architecture:** Two native tab pages with editor/member pages; authenticated versioned REST API; SQLAlchemy models and explicit Alembic migration; UTC minute timestamps and Beijing reporting.
**Spec:** The user's approved plan in this conversation; all privacy and role rules are binding.

## Global constraints
- Personal records are private even from company operators/owners.
- Company roles are per membership; ordinary members see only their schedules.
- Multiple companies, invitation join, no punches or approval workflow.
- No existing Git repository; work in the supplied empty project. Do not create unrelated worktrees or commits.

## Review focus
- Authorization revocation and old schedules after rejoining a company.
- Transactional version checks and idempotency under duplicate/concurrent requests.
- Beijing calendar splits including month/year transitions.
- Conflict metadata must never reveal another company's activity to operators.
- Network failures must preserve forms and retries must not duplicate creates.

## Tasks
1. API behavior tests: write pytest integration tests for authentication, privacy, work-log totals, company roles, invitations, schedule conflicts/versioning and revocation. Run RED before implementation.
2. Backend: implement app factory, settings, models, authentication and domain routers; run pytest GREEN. Interface: /api/v1/auth, /work-logs, /companies, /my-schedules; bearer tokens; structured error detail; Idempotency-Key for creates; UTC ISO timestamps.
3. Database/operations: explicit initial Alembic revision, SQLite backup with retention and integrity check, deployment examples. Exercise migration and backup restore on temporary databases.
4. Mini program: two tabs plus log editor, schedule editor and company management; API client, date helpers and authorization-aware UI. Write executable Node tests for minute/timezone arithmetic, transport errors and conflict retry before helper implementation. Check all JS and JSON.
5. Review and delivery: run full test suites, migration upgrade/downgrade, syntax checks; fresh whole-project review; fix findings and rerun relevant checks. Document developer-tool and phone tests as pending unless actually performed.
